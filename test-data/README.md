# Тестовая база DanceAdmin (вымышленная)

Все люди, телефоны и фото вымышлены. Студия: 3 зала, 9 направлений, 7 тренеров (1 в архиве), 19 шаблонов расписания.
Дата перехода на DanceAdmin — **01.10.2026**, электронная история — **01.10–13.10.2026**.

## Специально заложенные ситуации

- **Должники** — ~10% перенесённых абонементов оплачены частично; часть долгов погашается после перехода (`purpose: "debt"`).
- **Закончившиеся абонементы** — у части клиентов абонемент закончился к 01.10 или в течение 01–13.10; большинство продлевают, ~25% нет.
- **Клиенты в группе без абонемента** — в списке занятия должны быть с кнопкой «Продать».
- **Несколько абонементов** — у клиентов с продлением по 2 абонемента; есть безлимиты (`lessonsTotal: null`).
- **Дети** — `guardianName`; часть детей — братья/сёстры с **одним телефоном мамы** (дубль по телефону — предупреждение, не запрет).
- **Заморозки** (лимиты — в `membershipTypes.maxFreezeDays / maxFreezeCount`):
  - `F-001` — прошедшая, 05–11.10, болезнь;
  - `F-002` — на 08–21.10, но **разморожен досрочно** 11.10 (`actualToDate`) — засчитываются 4 дня;
  - `F-003` — **действует сегодня (14.10)** → статус ❄ «Заморожен»;
  - `F-004` — будущая, 16–29.10, ровно на лимите 14 дней.
  Во время заморозки посещений нет; дата окончания абонемента в файле — исходная, программа сдвигает её сама.
- **Посещения «в долг»** — пара клиентов пришла без абонемента: продан «Разовое занятие» без оплаты → появляется долг 700 ₽.
- **Пробное занятие** — каждый новый клиент приходит по `MT-TRIAL`.
- **Отменённое занятие** — Растяжка 07.10 19:00 (`status: "cancelled"`, причина).
- **Замена тренера** — 05.10 18:00 и 09.10 11:00 (`originalTrainerId`).
- **Возвраты** — частичный с аннулированием абонемента, частичный-компенсация с сохранением абонемента, полный за неиспользованный абонемент.
- **Аннулированное посещение** — одно, с причиной (`annulledAt`, `annulReason`).
- **Без согласия на ПД** — ~7% клиентов без `pdConsentAt`.
- **Архивный тренер** — `T-007` (не должен предлагаться в расписании).
- **Вместимость залов** соблюдена: Большой — 24, Маленький — 14, Третий зал — 18.
- **Направления (вымышленный набор):** Танцевальный фитнес, Йога, Стретчинг, Джаз-фанк, Хип-хоп, Детская хореография, Латина, Контемпорари, Фитнес-микс.
- **Абонементы не привязаны к направлениям**, группы не фиксированы — на любое занятие может прийти любой клиент.
- **Абонементы «заранее»:** 3 купленных, но ещё не начатых (`startDate` пустая, есть `waitUntil`) — стартуют с первого посещения или сами после срока ожидания.
- **Дети:** у клиентов детской группы `isKid: true` и `kidGender` (boy/girl) — в программе значок 👦/👧.

## Формат (schemaVersion 1)

Связи — по `externalId`. Деньги — целые рубли. Даты — `YYYY-MM-DD`, дата-время — ISO 8601 с `+03:00`.

| Коллекция | Ключевые поля |
|---|---|
| `halls` | `externalId`, `name`, `capacity`, `color` |
| `directions` | `externalId`, `name`, `color` |
| `membershipTypes` | `externalId`, `name`, `lessonsCount` (null = безлимит), `durationMonths` (если нет — считается из `durationDays`), `price`, `trainerRate` (₽ тренеру за посещение) |
| `trainers` | `externalId`, ФИО, `phone`, `directions`, `color`, `photo`, `isArchived` |
| `scheduleTemplates` | `directionId`, `trainerId`, `hallId`, `daysOfWeek` (1=пн…7=вс), `startTime`, `durationMin`, `validFrom` |
| `clients` | ФИО, `phone` (+7XXXXXXXXXX), `guardianName`, `birthDate`, `firstVisitDate`, `source`, `pdConsentAt`, `note`, `noteImportant` (красный флажок), `isKid`, `kidGender` (boy/girl), `photo`, `isArchived` |
| `memberships` | `clientId`, `typeId`, `lessonsTotal`, `price`, `purchasedAt`, `startDate`/`endDate` (пустые = ещё не начат), `months`, `waitUntil`, `autoStarted`, `usedBeforeMigration`, `status` (normal/annulled), `isMigrated` |
| `lessons` | `templateId`, `directionId`, `trainerId`, `hallId`, `startsAt`, `endsAt`, `status`, `cancelReason`, `originalTrainerId` |
| `visits` | `clientId`, `lessonId`, `membershipId`, `lessonNumber`, `markedAt`, `markedBy`, `method` |
| `payments` | `clientId`, `membershipId`, `purpose` (membership/debt/rent/other), `amount`, `paidAt`, `method` (cash/card/transfer/other), `isMigrated`, `adminName` |
| `freezes` | `membershipId`, `clientId`, `fromDate`, `toDate`, `actualToDate` (досрочная разморозка), `reason`, `comment`, `createdAt`, `adminName` |
| `refunds` | `paymentId`, `clientId`, `membershipId`, `amount`, `refundedAt`, `method`, `reason`, `membershipAction` (annul/keep/reduceLessons) |

Коллекция `groupMembers` больше не используется (группы не фиксированы) и при импорте пропускается.

Поля, начинающиеся с `_` (`_comment`, `_expected`), — служебные пояснения, импорт должен их игнорировать.
`markedBy` / `adminName` — текстовые имена (пользователи программы не импортируются из соображений безопасности).
